# OODA 行为测试

本目录包含用于验证 `ooda` skill 的可复用行为场景。

这些是指令级测试，不是可执行的单元测试。它们旨在回答一个问题：

> 当前写好的 skill 规则是否足以强制 Agent 在此场景中正确行事？

## 文件

- `behavior-scenarios.yaml`：标准场景用例——40 个场景，带版本号，机器可读。它才是权威场景清单；下方「覆盖范围」只是它的人类可读索引，不是替代品。
  - 该文件头部的 `rule_anchors` 把每一个 `required_rules` 取值映射到规则的真实位置。场景用到的每个取值都必须在这里登记。这是这个文件自带的交叉一致性检查——3.8.0 版曾指向一条已经不存在的规则名（`Coding And Skill Package Checklist`），而这正是 v5.2.0 要消掉的那一类缺陷。
  - `verification_status` 三个取值：`static`（读过规则原文，所指规则确实能约束该行为）、`behavior`（真的在新会话里发过这条提示词，观察到的行为相符）、`pending-behavior`（目前只有静态核验，还欠一次真跑）。不要在改过规则的同一个会话里把场景提升为 `behavior`——那是自证。

## 使用方法

跨主机测试步骤、证据格式和验收门槛见 [`TEST-PLAN.zh-CN.md`](TEST-PLAN.zh-CN.md)。先在 skill 根目录运行 `node tests/smoke-test.mjs`；静态通过不等于新会话行为通过。`expected_result: pass` 的意思是「Agent 符合预期行为」，包括该拒绝时拒绝，不能据此断言没有反例测试。

针对每个场景：

1. 阅读提示词和风险点。
2. 将预期行为与当前 `SKILL.md` 进行对比。
3. 将结果标记为 `pass`、`partial` 或 `fail`。
4. 如果某个场景未通过，更新本该约束该行为的 skill 规则。

## 覆盖范围

当前场景覆盖：

- 模糊目的的处理。
- 琐碎任务不触发。
- 微循环文档修复。
- 中循环 skill 更新。
- 高风险/破坏性动作暂停。
- 首次修复失败后自动重跑。
- 路径正确性验证。
- 英文默认运行时下的中文用户交互。
- state-R{N}.md 每轮快照不覆写与跨轮次任务连续性；每轮融合 ADR；真实时间戳；依赖 summary.restore_anchor + state-R{N}.md 的 A 段实现压缩后恢复。
- 原有确认问题与弹框优先/对话兜底、仅依赖 OODA 的战略反证审查、自适应标准/严格分流、蜂群不可用时如实降级、真实致命场景与严格模式的三层互异证据。
- 「三说一决」的用户价值确认、因果链证据、可安全执行的反证以及未运行测试不得算通过的决策门槛。
- 缺弹框时编号对话提问；回答不全须暂停，逐项确认后继续原有循环。
- 结构性 skill 升级在确认后默认严格：一行触发变更也算结构性，局部文案修改仍走轻量路径。
