# OODA Skill

`ooda` 是一个 Codex skill，用于强制执行 OODA 循环直到任务被验证解决。适用于模糊工作、迭代修复、skill 验证、代码变更、审查，以及任何需要澄清目的、执行、验证、自动重跑的复杂任务。

原有用户确认检查点、5W1H 和理解与提问流程保留：有 `AskUserQuestion` 时优先弹框；缺失时用编号对话提问，等待用户逐项明确答复，并记录确认通道。确认后，改变触发、路由、确认、状态/回滚契约、跨宿主安装或多文件依赖运行规则的结构性 skill 升级默认采用严格保障；仅改局部文案、错字或只读查询仍走轻量路径。严格模式内置「战略反证审查」、真实致命场景、三层不同证据和破框复核；静态检查不能冒充新宿主行为验证。

战略反证审查使用**三说一决**：确认用户价值标准、以证据追踪因果链、以安全的真实场景尝试证伪，再形成可追溯的决定。未运行的测试绝不算验证通过。

## 语言版本

- 默认英文版：`SKILL.md`
- 中文版：`SKILL.zh-CN.md`
- 运行时默认入口为英文版，便于 GitHub 和跨 agent 复用。面向用户的回复仍跟随用户所用语言。

## 安装与使用

OODA 支持多个 AI Coding Agent 环境，安装方式相同：将 skill 文件放到对应环境的 `skills/` 目录下。

### 各环境安装路径

| 环境 | 全局路径 | 项目路径 | 调用方式 |
|------|---------|---------|---------|
| **CodeFuse/百炼** | `~/.codefuse/engine/cc/skills/ooda/` | — | `/ooda` |
| **Claude Code** | `~/.claude/skills/ooda/` | `.claude/skills/ooda/` | `/ooda` |
| **Codex** | `~/.codex/skills/ooda/` | `.codex/skills/ooda/` | `/ooda` |
| **Kilo Code** | `~/.kilocode/skills/ooda/` | `.kilocode/skills/ooda/` | `/ooda` |

### 快速安装

**Windows (PowerShell):**
```powershell
.\install.ps1
```

**Mac / Linux / Git Bash:**
```bash
bash install.sh
```

脚本会自动检测当前环境和已安装的 Agent，创建链接到对应路径。

### 手动安装

```bash
# 以 Claude Code 全局安装为例
cp -r ./ooda-skill/* ~/.claude/skills/ooda/
# Windows 下安装后重启 Agent 并确认 /ooda 可被发现；若失败再同机对照 LF / CRLF
```

### 使用

在任意 Agent 中输入 `/ooda` 加上你的任务：

```
/ooda 为当前项目添加用户认证模块，需要考虑安全性和性能
```

OODA 会自动：
1. 在状态栏创建 5 个任务节点显示进度——仅走循环路线时如此；琐碎与分析路线不建任务列表
2. 优先通过 **AskUserQuestion** 弹框确认理解；不可用时用编号对话提问并等待用户明确回答
3. 多轮循环验证，不解决问题不停止
4. 所有过程记录写入 `work_ooda/` 目录——仅走循环路线时如此

### 注意事项

- **Windows**：行尾符本身不能证明能否发现 skill。安装后重启 Agent，在新会话验证 `/ooda`；若发现失败，用相同主机和版本、相同内容的 LF / CRLF 副本对照，记录环境与结果，再判断是否与换行有关。详见 [`tests/TEST-PLAN.zh-CN.md`](tests/TEST-PLAN.zh-CN.md)。
- **CodeFuse**：skill 发现路径为 `~/.codefuse/engine/cc/skills/`，与标准 Claude Code 不同
- **状态栏**：仅在 Claude Code / CodeFuse 中支持，Codex 会降级为文本进度
- 安装后需**重启 Agent 会话**才能识别新 skill

## 当前能力

- 执行前判断任务复杂度：琐碎任务直接跳过 OODA——除非任务会写入或执行到不可逆目标（生产环境或线上配置、功能开关、凭证、数据迁移或删除、发布部署、资金、权限），此时档位升一档，且在动手之前必须取得明确确认并写清回滚路径。四档全部评估一遍、取命中的最大那一档；选中的路线在第一行输出中声明，使分流错误可被看见并纠正。
- **强制执行"理解与提问"阶段**：在明确目的之后、第一轮之前——列出所有未知项，一次性批量提问，等待全部回答，总结理解，用户确认后才进入执行。
- **5W1H 发散扫描**：在理解回执之后、形成 U&Q 问题之前，Agent 系统性扫描 Who/What/Where/When/Why/How 六个维度。每个维度记录已知、模糊、待探索——确保 U&Q 问题是系统性扫描的产出，而非临时想到什么问什么。
- **数据对账诊断模式**：当 Observe 发现数据对不上（两个应该一致的值/记录/状态不一致）时，本轮从"修复问题"切换为"找到分叉点"。追溯矛盾双方完整数据链路，定位分叉点。如果根因在可观测范围外，产出结构化诊断手交报告，不猜测性修复。
- 先澄清用户真实目的再行动。
- 将 OODA 过程记录（含 Q&A 的目的文件、每轮报告、总结）写入当前项目目录下的 `work_ooda/{YYYYMMDD-HHMMSS}-{任务名}/`。任务交付物写入项目约定位置，禁止放入 `work_ooda/`。
- 创建 `00-purpose.md`，每轮一个文件如 `01-round-1.md`，`state-R{N}.md` 检查点文件（每轮新增一份、不覆写，保证任务连续性），以及 `summary.md`。
- 每轮重新读取相关文件，不依赖记忆。
- 使用问题分级：`critical`、`major`、`minor`、`cosmetic`。
- 第二轮起执行 Delta 对比检查。
- 每轮锁定当前 Decide 范围。
- 每轮融合 ADR 记录（问题背景 + 备选方案 + 各方利弊 + 决策理由 + 后果 + 关联），让每个决策可追溯。
- 每轮文件 frontmatter 与每条命令都带真实时间戳；任务目录用真实 HHMMSS 命名，不再用 000000 占位。时间由明确的命令取得（`date '+%Y-%m-%dT%H:%M:%S%z'`，PowerShell 用 `Get-Date -Format o`），其原始输出与其他命令一样记入记录；没有 shell 可用时，该轮声明 `time_source: unavailable` 并只用日期粒度——声明出来的局限不算编造。
- summary.md 加恢复锚点 restore_anchor，每个 state-R{N}.md 加 A 段任务自述：上下文被压缩后，新 Agent 仅凭 summary + 最新 state-R{N}.md + 00-purpose.md 即可恢复任务/上下文/目标，无需重读每轮。
- **原生状态栏集成**：通过 `TaskCreate`/`TaskUpdate` 创建 5 个顺序任务，展示完整 OODA 思考链（理解问题→对齐提问→诊断定向→决策执行→验证关闭），带每轮标记（R1/R2/...）。多轮迭代自动运行直到验证解决。
- **路由门在最前**：「目的优先」是文件的第一节，先于任何其他指令执行。`Route:` 行在创建任何任务之前声明，任何路线都不可能被无意采用。只有声明了循环路线之后，第一个动作才是创建任务 1。
- **四档判定，取最大命中**：琐碎、分析、微循环、中循环、宏循环。档位由四档给出初值、由「循环规模」表最终确定；两者不一致时以「循环规模」表为准，并在路线行上记录分歧。
- **规模不构成升级理由**：文件数不是触发条件。跨任意数量文件的机械批次，只要不含设计决策就仍是琐碎路线——但涉及超过 5 个文件的批次，必须报告执行的命令、改动文件数与至少 3 处带路径的抽检。
- **不得静默跳过**：允许走短路线，但必须在输出第一行说明所走路线及原因。
- **可靠性由用户评判**：用户在 U&Q 理解确认、Decide 方案、Close 关闭三个检查点确认方向。Agent 提供清晰证据，用户做最终判断。
- 自动进入下一轮，直到问题被验证解决。
- 目的、上下文、风险或取舍不明确时，向用户提问而非猜测。
- **用户叫停时有未解决问题，追问一次。** 只在用户同意时才记录为遗留问题。
- 同一问题连续两轮修复失败后暂停。

## 维护说明

- `SKILL.md` 的 frontmatter 保持精简以兼容 Codex：仅 `name` 和 `description`。
- 详细理论放入 `references/`，不要放入活跃 skill 主体中，除非会改变运行时行为。
- 可复用的对比和复盘记录放在当前项目的 `work_ooda/` 下；临时验证日志放在 `output/` 下并忽略，除非刻意发布。
- `SKILL.md` 为默认英文运行时入口。中文运行时指引在 `SKILL.zh-CN.md`。
- 行为变更时，在版本历史表中追加一行。仅打包层面的改动不属于行为变更，不追加行。

`ooda` 是一个五仓 agent skill 生态里的「执行纪律」层：下面的编排引擎把它当能力层挂载，另外三个仓是同族 skill，产出走同一套输出结构。

| 仓库 | 是什么 | 与 `ooda` 的关系 |
|---|---|---|
| [aiqianqian521/sloth-loop](https://github.com/aiqianqian521/sloth-loop) | 零 LLM 的任务编排引擎（身体） | 驱动 OODA 轮次，通过 `skills/ooda` 子模块挂载本 skill |
| [aiqianqian521/architect-skills](https://github.com/aiqianqian521/architect-skills) | 19 个架构评估 skill（Agent / RAG / 安全 / 合规 / 可观测性 / 成本…） | 同族 skill，产出走统一的输出结构 |
| [aiqianqian521/obsidian-skills](https://github.com/aiqianqian521/obsidian-skills) | 14 个 Obsidian 知识库 skill | 同族 skill，产出走统一的输出结构 |
| [aiqianqian521/ai-skill-output-template](https://github.com/aiqianqian521/ai-skill-output-template) | 声明式多模板注册中心 | 定义全族 skill 共同遵守的报告输出结构 |
